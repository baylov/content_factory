# Ультра-быстрый JS парсер с проверкой селекторов

## 🎯 Цель
Сделать парсер который **< 1 секунды** на цикл И **гарантированно находит новости**.

## 📋 Реализованные функции

### 1. `debug_save_html_and_find_selectors(driver)` - Диагностика
**Назначение:** Сохраняет HTML страницы и тестирует различные селекторы для поиска новостей.

**Что делает:**
- Сохраняет полный HTML страницы в `upbit_debug.html`
- Тестирует 8 различных CSS селекторов
- Показывает количество найденных элементов для каждого селектора
- Выводит примеры найденных ссылок (первые 3)
- Рекомендует лучший селектор

**Когда используется:**
- Автоматически при ошибке парсинга (не найдены новости)
- Можно вызвать вручную для диагностики

**Пример вывода:**
```

💾 HTML сохранен в upbit_debug.html
🔍 Тестируем селекторы:
  🔍 Селектор 'a[href*="/service_center/notice?id="]': найдено 25 элементов
     📄 [공지] Upbit 서비스 점검 안내 -> /service_center/notice?id=5710
     📄 Bitcoin 입출금 일시 중단 안내 -> /service_center/notice?id=5709
     📄 Ethereum 입출금 재개 안내 -> /service_center/notice?id=5708
  🔍 Селектор 'a[href*="/service_center/notice"]': найдено 25 элементов
✅ ЛУЧШИЙ СЕЛЕКТОР: 'a[href*="/service_center/notice?id="]' (25 элементов)
💡 РЕКОМЕНДАЦИЯ: Используйте селектор 'a[href*="/service_center/notice?id="]'
```

### 2. `wait_for_notices_js(driver, max_wait=1.0)` - Умное ожидание
**Назначение:** Ждет появления новостей, проверяя каждые 50ms вместо статического sleep.

**Параметры:**
- `driver` - WebDriver instance
- `max_wait` - максимальное время ожидания (по умолчанию 1.0 сек)

**Возвращает:**
- `True` - если новости появились
- `False` - если timeout

**Преимущества:**
- Не тратит время впустую: возвращается сразу когда новости появились
- Проверяет каждые 50ms вместо ожидания фиксированного времени
- Оптимально для производительности

**Пример вывода:**
```
⚡ Новости появились за 0.234s
```

---

### 3. `get_all_notice_ids(driver)` - Парсер с fallback стратегиями
**Назначение:** Извлекает ID новостей через JavaScript с умными fallback стратегиями.

**Приоритеты:**
1. **Приоритет 1:** НАЙТИ новости (правильный селектор)
2. **Приоритет 2:** Сделать быстро (< 1 сек)

**Fallback стратегии:**
1. **Стратегия 1 (exact_id):** `a[href*="/service_center/notice?id="]` - точный селектор
2. **Стратегия 2 (notice_links):** `a[href*="/service_center/notice"]` - любые ссылки с notice
3. **Стратегия 3 (tr_notice):** `tr a[href*="notice"]` - ссылки в tr с notice
4. **Стратегия 4 (any_id):** `a[href*="id="]` - любые ссылки с id параметром

**Фильтрация закрепленных новостей:**
Пропускает закрепленные новости (pinned) несколькими способами:
- Проверка текста на маркер `공지` (공지 = "объявление" на корейском)
- Проверка на иконку pin (`[class*="pin"]`, `svg[class*="pin"]`)
- Проверка класса row (`pinned`, `fixed`, `notice`)

**Автоматическая диагностика:**
При ошибке или если новости не найдены, автоматически запускает `debug_save_html_and_find_selectors()`

**Детальные метрики:**
```
✅ Найдено 20 новостей (strategy: exact_id, total links: 25)
🔢 ID: [5710, 5709, 5708, 5707, 5706]...
⏱️ Время парсинга: 0.023s
⚡ Отлично: 0.023s < 0.5s!
```

**При ошибке:**
```
❌ Новости не найдены!
   Strategy: exact_id
   Total links found: 0
💡 Запускаем диагностику...
🔍 ДИАГНОСТИКА: Начинаем анализ страницы...
```

## 🔧 Настройки

### Интервалы
- **Polling интервал:** 50ms (0.05 сек) - проверка появления новостей
- **Max wait:** 0.5 сек - максимальное ожидание новостей
- **Fallback sleep:** 0.5 сек - дополнительное ожидание если новости не появились
- **Refresh интервал:** 1-2 сек - случайный интервал между refresh

### Оптимизации
- `page_load_strategy='eager'` - не ждет загрузки всех ресурсов
- Блокировка изображений, CSS, media, fonts
- Умное ожидание вместо статического sleep
- JavaScript парсинг (быстрее чем Selenium селекторы)
- Переиспользование WebDriver

## 🔍 Диагностика проблем

### Если новости не находятся
1. Автоматически запускается `debug_save_html_and_find_selectors()`
2. Создается файл `upbit_debug.html` с полным HTML страницы
3. Тестируются все селекторы и выводятся результаты
4. Предлагается лучший селектор

### Если парсинг медленный
1. Проверьте метрики в логах:
   - `Загрузка:` - время загрузки страницы
   - `Ожидание:` - время ожидания появления новостей
   - `Парсинг:` - время извлечения ID
2. Определите узкое место
3. Проверьте сетевое подключение

### Логи
- **Основной лог:** `logs/bot.log` - весь вывод бота
- **Метрики:** `logs/performance_metrics.log` - детальные метрики обработки новостей
- **Диагностика:** `upbit_debug.html` - HTML страницы при ошибках
