# Task: Unify Selector Logic with Diagnostic

## Задача

Унифицировать логику fallback стратегий между основным парсером и диагностикой для устранения нестабильности парсинга.

## Проблема

**Симптомы:**
- Бот работал нестабильно - 50% циклов успешные, 50% неудачные
- Успешные циклы: `exact_id` находил 22 новости за 1.5-1.6s
- Неудачные циклы: `notice_links` находил только 3 новости вместо 23, затем запускалась диагностика

**Корень проблемы:**
Различные функции использовали разные селекторы:
- `get_all_notice_ids()` - основной парсер с fallback стратегиями
- `wait_for_notices_js()` - использовал только широкий селектор
- Quick check - использовал только точный селектор
- `debug_save_html_and_find_selectors()` - диагностика (правильные стратегии)

Результат: несогласованность приводила к тому, что функции ожидания и парсинга искали разные элементы.

## Решение (v2.3)

### 1. Унификация fallback стратегий

**Все 4 функции теперь используют ОДИНАКОВЫЕ стратегии:**

```javascript
// Стратегия 1: exact_id
'a[href*="/service_center/notice?id="]'

// Стратегия 2: all_notice (было: notice_links)
'a[href*="/service_center/notice"]'

// Стратегия 3: tr_notice
'tr a[href*="notice"]'

// Стратегия 4: any_id
'a[href*="id="]'
```
