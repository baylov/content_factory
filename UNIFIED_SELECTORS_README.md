# Унификация селекторов (v2.3)

## Проблема

Бот работал нестабильно - через раз парсинг успешный, через раз падал:

**✅ Успешные циклы:**
```
Strategy: exact_id
Найдено 22 новостей
⏱️ 1.5-1.6s
```

**❌ Неудачные циклы:**
```
Strategy: notice_links  
Total links found: 3 (вместо 23!)
❌ Новости не найдены!
Запускается диагностика...
⏱️ 1.8-2.0s
```

## Корень проблемы

Основной парсер и диагностика использовали **разные селекторы**.

- **Диагностика** всегда находила 26 элементов с селектором `'a[href*="/service_center/notice"]'`
- **Основной парсер** иногда использовал стратегию `notice_links`, которая находила только 3 элемента
- **wait_for_notices_js()** использовал только широкий селектор `'a[href*="/service_center/notice"]'`
- **Quick check** использовал только точный селектор `'a[href*="/service_center/notice?id="]'`

Результат: несогласованность между функциями приводила к ситуации, когда:
1. Quick check не находил элементы с `?id=`
2. wait_for_notices_js() ждал появления элементов с `/notice`
3. get_all_notice_ids() пытался сначала `exact_id`, потом `notice_links`
4. notice_links находил только частично загруженную страницу (3 элемента)

## Решение (v2.3)

### 1. Унификация fallback стратегий

**ВСЕ функции теперь используют ОДИНАКОВЫЕ 4 fallback стратегии:**

```javascript
// Стратегия 1: Точный селектор с ?id=
'a[href*="/service_center/notice?id="]'  → strategy: 'exact_id'

// Стратегия 2: Любые ссылки с notice  
'a[href*="/service_center/notice"]'      → strategy: 'all_notice'

// Стратегия 3: Ссылки в таблице
'tr a[href*="notice"]'                   → strategy: 'tr_notice'

// Стратегия 4: Любые ссылки с id=
'a[href*="id="]'                         → strategy: 'any_id'
```

### 2. Переименование стратегии

`notice_links` → `all_notice` - более понятное и точное название

### 3. Обновленные функции

#### `get_all_notice_ids(driver)`
- Использует все 4 fallback стратегии в правильном порядке
- Логирует используемую стратегию
- Логирует общее количество найденных ссылок (до фильтрации)

```python
logging.info(f"✅ Найдено {result['count']} новостей (strategy: {result['strategy']}, total links: {result['totalLinks']})")
```

#### `wait_for_notices_js(driver, max_wait=0.3)`
- Теперь использует **те же 4 fallback стратегии**
- Проверяет каждую стратегию по порядку
- Возвращает True, как только любая стратегия находит элементы

```javascript
// Стратегия 1: Точный селектор
let count = document.querySelectorAll('a[href*="/service_center/notice?id="]').length;

// Стратегия 2: Любые ссылки с notice
if (count === 0) {
    count = document.querySelectorAll('a[href*="/service_center/notice"]').length;
}

// Стратегия 3: Ссылки в таблице
if (count === 0) {
    count = document.querySelectorAll('tr a[href*="notice"]').length;
}

// Стратегия 4: Любые ссылки с id=
if (count === 0) {
    count = document.querySelectorAll('a[href*="id="]').length;
}
```

#### Quick check в `get_all_notice_ids_with_api()`
- Использует **те же 4 fallback стратегии**
- Проверяет страницу сразу после загрузки
- Если находит элементы - пропускает ожидание

### 4. Улучшенное логирование

**Каждый успешный цикл:**
```
✅ Найдено 22 новостей (strategy: exact_id, total links: 23)
🔢 ID: [5710, 5709, 5708, 5707, 5706]...
⏱️ Время парсинга: 0.234s
⚡ Отлично: 0.234s < 0.5s!
```

**При ошибке:**
```
❌ Новости не найдены!
   Strategy: all_notice
   Total links found: 3
💡 Запускаем диагностику...
```
